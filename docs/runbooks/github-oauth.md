# Sign in with GitHub locally

DevGrill signs people in with GitHub only (owner decision; ADR 005, ADR 011). Locally you need your own **GitHub OAuth App**. It takes about two minutes, and you only do it once per machine.

Automated tests never need this: they use a mock GitHub (`apps/web/e2e/mock-github.mjs`).

## 1. Create the OAuth App

1. Open <https://github.com/settings/developers>, choose **OAuth Apps**, then **New OAuth App**.
2. Fill in:

   | Field | Value |
   |---|---|
   | Application name | `DevGrill (local)` |
   | Homepage URL | `http://localhost:3000` |
   | Authorization callback URL | `http://localhost:3000/api/auth/callback/github` |
   | Enable Device Flow | leave unticked |

3. Select **Register application**.
4. Copy the **Client ID**. Then select **Generate a new client secret** and copy the secret; GitHub shows it only once.

## 2. Put the credentials in `.env`

In the repo-root `.env` (never committed):

```dotenv
GITHUB_CLIENT_ID=<the client id>
GITHUB_CLIENT_SECRET=<the client secret>
# Optional: your GitHub login gets the admin role (content console) on next sign-in.
ADMIN_GITHUB_LOGINS=<your-github-login>
```

`BETTER_AUTH_SECRET`, `INTERNAL_HMAC_SECRET` and `GUEST_TOKEN_SECRET` are generated by `just setup`. If any is empty, run `just setup` again.

## 3. Run it

```powershell
just db-migrate   # app schema (Alembic) + auth schema (Better Auth)
just db-seed      # tracks, topics and scenarios from content/
just dev
```

Open <http://localhost:3000/sign-in> and choose **Continue with GitHub**. After you approve, you land on the drills page signed in. Your profile handle is your GitHub login.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| GitHub says "The redirect_uri is not associated with this application" | The callback URL must be exactly `http://localhost:3000/api/auth/callback/github` (http, port 3000, no trailing slash) |
| You return to `/sign-in?error=1` | Usually a wrong client secret. Generate a new one and update `.env` |
| You're signed in, but pages say the API didn't answer | The API isn't running, or `BETTER_AUTH_URL`, `AUTH_ISSUER` and `AUTH_JWKS_URL` don't match where the web app runs |
| The admin console says you need the admin role | Add your login to `ADMIN_GITHUB_LOGINS`, then sign out and in again (roles are applied at sign-in) |

## Production (later, Track H)

Create a separate OAuth App for the real domain. Its callback is `https://<domain>/api/auth/callback/github`. Set the same variables in the deployment's secret store, never in a file.
